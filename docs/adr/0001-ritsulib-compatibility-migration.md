# 以兼容性迁移作为一期重构边界

一期重构将 BaseLib 替换为 RitsuLib，并重构内容注册、补丁编排、资源路径、本地化和配置基础设施。我们保留既有内容名称、设置语义与玩家可见玩法行为；RitsuLib 会规范化旧 Model ID，因此同一改动中迁移所有对应本地化 key 和资源命名解析。任何刻意的平衡或玩法改动留待后续独立任务处理。迁移期间，`master` 继续作为 BaseLib 的可发布维护线，RitsuLib 在独立长期分支验证通过后整体切换。

本地开发由 RitsuLib NuGet 的部署 target 作为运行时文件的唯一来源；必须只保留其 `mod_manifest.json`。先前开发安装残留的 `STS2-RitsuLib.json` 会让游戏扫描到同一 Mod ID 两次，因此构建会主动删除该旧文件。

RitsuLib 使用 NuGet 浮动版本并在每次构建时强制重新求解，以跟随游戏与框架的上游稳定版。manifest 只声明框架 ID，不把运行时锁死在某个补丁版本；本地由 NuGet 自动部署已解析的同一版本，发行安装说明要求玩家使用与游戏版本兼容的最新稳定版。

源码采用参考项目的 `src/` 结构：`BalanceModEntry` 是唯一初始化入口；`Abstract/` 是共享内容模板这一深模块；具体内容按类别并列；`Runtime/` 仅承载视觉、音频和战斗状态等运行时实现。这样内容模型只依赖模板接口，而不需要了解资源路径、设置或运行时细节。

## Considered Options

- 在迁移过程中同时重做玩法与内容 ID。放弃：运行时回归和存档兼容问题将无法归因。
- 保持 BaseLib，只局部整理路径。放弃：无法消除目前的基础库耦合和功能缺口。

## Consequences

卡牌与遗物显式声明稳定的 RitsuLib Public Entry；其余独立模型采用 RitsuLib 的 `MOD_CATEGORY_TYPE` 规则。资源与本地化必须从同一规范化 ID 或内容类型推导，避免路径与注册 ID 漂移。

`master` 的紧急修复需要同步到迁移分支；迁移分支在完成前不得作为正式发布版本。
